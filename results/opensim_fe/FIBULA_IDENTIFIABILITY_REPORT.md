## 0. 一句话结论

**根因是「FE 量级问题」，不是「σc 口径问题」。** 腓骨 FE 在踝关节处**吃到了与胫骨完全相同的整条踝反力**（`ankle_r` @5 m = 25 266 N），**没有做胫-腓载荷分配** —— 而生理上腓骨只承担约 **5–10%**（`bone.py::fibula_ends` / `risk_1d_loadshare.py` 文献锚）。结果腓骨的 σ_nom 被抬高到**同口径下胫骨的 13.775 倍**（两者 σc 同为 70 MPa、同关节、同降载），主设定 σ_nom = **419–3059 MPa**（中位数！已远超任何骨的材料强度）。**σc=70 MPa 正确**（[Y25] Table 1 腓骨两端压缩强度）；把 σc 一路升到表内最高压缩强度 **220 MPa** 腓骨**仍是 all_one** —— 任何生理 σc 都救不回来。故推荐动作 = **发起一次 FE 量级审计**（在 FE 链路补上胫-腓载荷分配 + 验证求解收敛/线性），**不是**改 σc，**也不是**永久记为限制。

## 3. (b) 根因判定 —— σc 口径 ✗ vs FE 量级 ✓

### 3.1 σc 口径问题：**排除**

σc=70 MPa 是 [Y25] Table 1 的**腓骨两端压缩强度**，恰是 route-乙 设计指定的**弱子区域**基准（骨折最爱发生在两端）。它不低、也不是错基准。**唯一能让腓骨脱离 all_one 的 σc 临界值是 418.552 MPa**（= min_h σ_nom），而 [Y25] 表内**最高的压缩强度只有 220 MPa**（股骨骨干）：

| σc 候选 (MPa) | 依据 | 过阈高度数 /50 | 是否 all_one |
|---:|---|---:|:--:|
| 70 | route-乙 弱区（腓骨两端，本件采用值） | 50 | 是 |
| 80 | 股骨颈量级 | 50 | 是 |
| 160 | [Y25] 腓骨**骨干** | 50 | 是 |
| 200 | [Y25] 胫骨骨干 | 50 | 是 |
| 220 | [Y25] 表内最高压缩（股骨骨干） | 50 | 是 |
| 418.55 | all_one 临界 σc*（非生理） | 50 | 是 |
| 419.55 | 仅 >σc* 才脱饱和（非生理） | 49 | 否 |

* 即：**σc ∈ [70, 220]（整个生理区间）无一能把腓骨 lift 出 all_one**；必须把 σc 抬到 ~419 MPa（超任何骨强度 ~2×）才行。
* 换**骨干口径**亦同：BC2 σ_nom 对 σc=160 的比值为 **2.616–19.116**，腓骨**仍 all_one**（first=1 m）。这与 G3 报告 §DoD-2「两口径在 3 个 A3 渐进部位上完全一致」自洽。
* ⇒ **σc 口径不是根因。**

### 3.2 FE 量级问题：**成立**（根因）

根因定位到 FE 载荷映射的**缺失的一环：踝关节载荷未在胫/腓间分配**。三条独立证据：

**证据 1 —— 同关节 = 同载荷，两骨各吃整条踝反力。**
`fracture_matrix.py` 对每骨取 `ref_load = loads[f"{part.joint}__vert"][ref_idx]`；而 `paper_alignment.REGIONS` 里胫骨与腓骨的 `joint` **同为 `ankle_r`**。故每根骨的 FE 都被施加**整条踝反力**：

| 量 | 值 |
|---|---|
| `ankle_r` 纵向峰值 @1 m / 5 m / 50 m | 15 454.5 / **25 266.2** / 112 933.9 N |
| 施加给 `tibia_r` FE 的参考载荷 | 25 266.2 N（**整条踝反力**） |
| 施加给 `fibula_r` FE 的参考载荷 | 25 266.2 N（**同样整条**） |
| 生理分担（文献锚） | 胫骨 ~90–95% / **腓骨 5–10%** |

**证据 2 —— 两骨 σ_nom 差 13.775×，而截面积只差 3.558×。** 同载荷、同 σc、同 fe_solve/lrf 下：

| 对照 | 腓骨 ÷ 胫骨 |
|---|---:|
| 截面 `A_section_mm2` | 362.65 ÷ 101.94 ⇒ **3.558×** |
| σ_nom（全主域 median，逐高度恒定） | **13.775×** |
| 均匀压缩估算 @5 m（F/A） | 247.86 MPa（腓骨） vs 69.67 MPa（胫骨） |

截面积只能解释 3.558× 里的一部分，剩下的 ~3.9× 来自「腓骨吃了本不该它吃的载荷 + 细长体 FE 的应力集中」。**把整条踝反力喂给 5–10% 分担的腓骨**，正是本项目早已识别的过估根因。

**证据 3 —— 腓骨 FE 求解本身不稳定、且无线性自检。**

| 项 | 腓骨 `fibula_r` | 胫骨 `tibia_r` |
|---|---|---|
| fe_solve_load_n | 5000 N（从 25 266 N 降到 1/5） | 5000 N |
| load_reduction_factor | **5.053×** | 5.053× |
| 降载搜索尝试 | 25266✗ / 10000✗ / **5000✓** / 2500✗（**非单调**） | 25266✗ / 10000✗ / 5000✓ / 2500✓ |
| 线性自检 `linearity` | **None（从未成功）** | ratio_median=3.233（期望 2.0） |
| legacy 口径（`fracture_matrix.json`） | fe_solve=1000 N，lrf=**25.266×** | — |

* 腓骨的收敛在载荷上**非单调**（2500 N 失败、5000 N 成功）⇒ 5000 N 这个选择不是物理承载极限，而是数值可解点的产物；lrf=5.053× 的线性外推**完全没有自检背书**。
* legacy 跑里腓骨甚至降到 1000 N（lrf=25.266×）——同一根骨两次相差 5×，进一步说明求解不稳。

**证据 4 —— 载荷分配反事实（仅诊断，不写回）。** 把腓骨 σ_nom 乘以其生理分担比后：

| 分担比 | 情形 | σ_nom/σc @h1 → @h50 | 是否出现 0/1 混合（logistic 有定义） |
|---:|---|---:|:--:|
| 1.000 | 现状（无分配） | 5.979 → 43.694 | **否（all_one）** |
| 0.232 | 纯并行刚度模型（非文献锚） | 1.389 → 10.152 | 否（仍 all_one） |
| **0.100** | 文献锚（同侧腓骨 ~10%） | 0.598 → 4.369 | **是** |
| **0.050** | 文献锚（单侧腓骨 ~5%） | 0.299 → 2.185 | **是** |

* 使腓骨 h=1 变安全的**临界分担比 = 0.1672**；文献锚的 5–10% 落在其下 ⇒ 一旦补上载荷分配，腓骨**立即从 all_one 变成有 0/1 混合**，logistic 有定义。
* 注意：**纯并行刚度模型（~23%）仍 >16.7% ⇒ 依然 all_one** —— 说明修法要选**文献锚的 5–10%**，不能想当然用等刚度并联。

### 3.3 判定

| 候选根因 | 判定 | 依据 |
|---|:--:|---|
| σc 口径（70 太低 / 基准错） | **✗ 排除** | 生理 σc 全区间 [70,220] 皆 all_one；临界 σc*=418.55 非生理 |
| FE 量级（单位错 / 面积错 / 远距强度） | **✓ 根因** | 无胫-腓载荷分配 ⇒ 腓骨 σ_nom 抬高 ~10–20×；同截面积只解释 3.6× |

> 细分：既不是「单位错」（MPa/N/mm² 自洽，均匀估算 F/A 与 FE 同量级），也不是「单纯远距强度」；是**载荷未分配**导致的**系统性量级放大**，并被**不稳定的降载折算**进一步污染。

## 4. (c) 与胫骨并排 —— 同为 σc=70，为何胫骨不 all_one

| 维度 | 腓骨 | 胫骨 | 差异 |
|---|---|---|---|
| 关节（参考载荷来源） | `ankle_r` | `ankle_r` | **相同** |
| σc（route-乙 弱区） | 70 MPa | 70 MPa | **相同** |
| fe_solve_load_n / lrf | 5000 N / 5.053× | 5000 N / 5.053× | **相同** |
| σ_nom 区间（BC2 median） | **418.552 – 3058.576 MPa** | 30.385 – 222.037 MPa | 腓骨 **13.775×** |
| σ_nom/σc 区间 | 5.979 – 43.694 | 0.434 – 3.172 | — |
| 确定性矩阵 | **all_one**（50/50） | 有 0/1 混合（~h≥9 全主域；ends h≈38 / shaft h≈5） | — |
| logistic | 无定义 | 有定义（G3 主设定 p 从 0 → 1） | — |

**差在哪：只差 FE 应力量级，且量级差来自「谁是主承重骨」。**
在真实小腿里，胫骨承担 **~90%** 轴向载荷、腓骨 **~5–10%**。FE 把**整条踝反力**喂给**每根骨**：

* 对**胫骨**：喂 ~100% ≈ 生理 ~90%，**近似正确** ⇒ σ_nom 量级合理（30–222 MPa）⇒ 有梯度；
* 对**腓骨**：喂 ~100% ≈ 生理 ~5–10% 的 **10–20 倍** ⇒ σ_nom 被放大到 13.775× 胫骨 ⇒ **一上桌就饱和**。

即：**胫骨「碰巧对」，腓骨「暴露了缺失的载荷分配」**。两者 σc 相同，故 all_one 与否**完全由 FE 量级决定**，与 σc 无关。

## 5. (d) 唯一推荐下一步 —— 发起一次 FE 量级审计（scoped）

**推荐动作：FE 量级审计（不是改 σc，也不是永久记为限制）。** 理由：根因是**已知且别处已修**的载荷映射缺陷（1D 力路已用 `load_fraction` 修好，FE 链路漏了），可修、应修；σc 无错可改；记为「永久限制」会掩盖一个真实可修缺陷。

**审计范围（4 项，锁定后执行）：**

1. **补胫-腓载荷分配**：在 FE 链路（`fracture_matrix.py` 的 `ref_load` 入口）对 `ankle_r` 反力按**文献锚**拆分 —— **胫骨 0.90–0.95 / 腓骨 0.05–0.10**（与 `bone.py::fibula_ends.load_fraction=0.05`、`risk_1d_loadshare.py::share_lit10/lit05` 一致）。**不使用**纯并行刚度比（其 ~23% 不足以脱饱和，见 §3.2 证据 4）。
2. **验证求解收敛性**：腓骨在**分配后**的参考载荷下重解，要求 (i) 降载搜索关于载荷**单调**、(ii) 双载荷**线性自检成功**（现状腓骨 `linearity=None`，必须补齐）。
3. **重出腓骨骨折矩阵行**，检查 logistic 是否恢复 0/1 混合（即 OR 是否有定义）；**不改 A3 规则、靶值、也不改已冻结的 G3 结果**（重跑是**新产物**，非重判）。
4. **附带**：复核其他「多骨共用一个关节反力」的行（如 L3/T6/C5/颅骨共用 `lumbar`）是否同类问题；这超出本件范围，仅登记。

**纪律**：审计跑完后，A3 是否变化**按新产物如实报**；**禁止**回解 σc 或分担比凑 ±30%。本件**不改** A3 = `PASS（2/3）`。

**明确不做**：① 不改 σc=70（无错）；② 不重跑 G3 MC；③ 不把 all_one 简化记为永久限制（根因可修）。

## 7. 诚实边界

1. 本件**未重跑任何 FE、未重跑 G3 MC**；所有数字取自**已冻结**产物 + 确定性算术。
2. §3.2 的载荷分配反事实是**诊断**，**不写回**任何矩阵，**不用于**凑 OR；它只回答「补上分配后是否可辨识」。
3. σ_nom 的绝对值还叠加了**FE 非线性外推误差**（胫骨线性自检 ratio_median=3.233 对期望 2.0 ⇒ 明显非线性；腓骨无自检）—— 故审计必须**先修收敛/线性**，否则任何 σ_nom 量级仍不可信。
4. 姊妹比 13.775× 的前提是两骨共享同一 `ankle_r` 反力且按同一线性因子缩放；该前提即现状代码事实。
5. 本件**不宣称**修正 A3、不宣称 G3 失败；`PASS（2/3）` 原样成立。腓骨所在行的「不可辨识」仍**如实存在**，直到 §5 的审计产出新产物。
6. 口径：本件只出现 **σ_nom/σc**（越阈物理量）与**载荷分担比**；不含任何 σ/σ_law 比值。
