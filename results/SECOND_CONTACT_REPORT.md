## 4. ★★ 新缺陷（本件最重要的产出）：`meta["f_flex_peak_n"]` 门路径口径不自洽

**证据**：`pad.py:828-833` 的后处理：
```python
f_flex = np.where(xf > 0.0,
    np.where(xf <= x_flex_max, k_flex*xf, k_flex*x_flex_max + k_stop*(xf-x_flex_max))
    + c_flex*rate_flex, 0.0)
```
**⇒ 它用**线性** `k_flex·xf`，**完全不含 `M(θ)` / `k_θ·θ`**；而 ODE（`rhs`）用的是两段腿门。**

**逐位验算**（`controlled-drop` @0.5 m）：`k_flex=2.2e5`、`xf≈0.12` ⇒
`2.2e5×0.12 + 400×rate ≈ 28.2 kN` = **实测 28.185 kN** ✓ **吻合**。

**⇒ 后果（严重）**：
- **C1 / C2 / D1 及本件的 `h*` 全部由这个观测量算出** ⇒ **判据与动力学不自洽**；
- 该观测量**随 `k_flex` 线性变化** ⇒ 换姿态（`k_flex` 2.2e5→1.6e5）表面差 9× **全是假象**；
- **⚠️ 但 ODE 轨迹不受影响**（`rhs` 用对的力律）⇒ `F_pad` 与我的 O1 重建仍然有效。
- ⇒ **⇒ 我先前「`k_flex` 在 C1/D1 下是死参数」的说法**部分错误**：它对**弹性项**成立，
  但**后处理观测量**仍按 `k_flex` 线性放大 ⇒ 我会在两处同时踩到它。

**修法（下一步，未做）**：后处理改为调用与 `rhs` **同一个** `flex_force`（单一真相源），
或直接由 `rhs` 输出的力序列导出；并对门路径加**断言**：`meta["f_flex_peak_n"]` 必须
与重建值一致（本会话第二次踩「诊断副本未同步」，见 `[LRN-20261016-1xx]`）。
