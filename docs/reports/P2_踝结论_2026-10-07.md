## 一、结论（一句话 + 三条支撑）

> **踝损伤第一次被算出来了：345 / 1000 = 34.5%，对 [B25] 实测 40.0%。**

⚠️ **「踝是第一大部位」在本模型内属平凡成立，不能当作 V5 的验证证据。**
模型能输出的 8 个部位里，7 个骨部位全部 0 骨折（最高利用率 0.72），
**踝是唯一非空项** —— 排序第一是"其余为零"的结果，不是比较出来的。
V5 真正要的是**分布形状**（下肢 67%、膝 15%、肘 16%…），模型**未复现**：
无膝/肘/上肢自由度，踝扭伤/骨折/脱位/韧带断裂的**类型拆分**也只覆盖了扭伤一项。
可验证的是**踝这一项的量级**（34.5% vs 40%，1.16x）与**机制**（V6/V9）。

支撑三条：

1. **相变结构复现（V6）**：`|sin β| > μ_slide` 是几何判据，天然重现 [T22] Table 4
   「低高度大角度 → 足滑动无骨折 / 低高度小角度 → 骨折 / 高高度无论角度都骨折」的结构，
   且存在「角度—高度」转变曲线。
2. **反直觉结论复现（V9）**：同 |β|、同高度下，外翻（β<0）的 `peak_ligament_strain`
   与 `ankle_bone_utilization` 均 **>** 内翻（β>0），跨高度稳定。
3. **踝单项对表 [B25]**：踝（扭伤或骨折）**345 / 1000 = 34.5%**，对 [B25] 实测 **40.0%**
   —— 单项量级吻合（**1.16x**）。**但绝对拆分 = 踝扭伤 34.5% / 踝骨折 22.8%**
   （MC 重跑后数值，见 §二），**结构上无法用单一标定逼近 [B25] 的 28%/8%** —
   见 §四「load-partition 标定分析」。

## 三、机制

**滑动 vs 卡住是几何相变**。判据 `|sin β| > μ_slide`（Coulomb 锥：
横向需求 `F_lat = N·sinβ` vs 承载力 `μ_slide·N`）**只依赖角度，与高度无关**。
`β` 落在 `{10°,20°,30°}` 时 `|sinβ|` 分别约 0.174 / 0.342 / 0.500，`μ_slide=0.4`
（`scripts/phase_p1_montecarlo.py` 的 `ROTATION_TO_POSTURE2D['longitudinal']` 提供）
⇒ 10°/20° **卡住**、30° **滑动**。

**骨折 = 撕脱（avulsion），不是弯曲破坏**。`[T22]` Table 4 的踝骨折临床机理是
**韧带把外踝 / 内踝撕下一块**，而不是腓骨中段弯曲。判据改为：
`F_lig_eff = F_lig · unload ≥ ANKLE_AVULSION_LOAD_N = 300 N`，
其中 `F_lig = |M|/r`、`unload = 0.005 if sliding else 1.0`。
滑动相把 `F_lig_eff` 按 `ANKLE_SLIDE_UNLOAD` 卸载：

- **低高度 + 大角度 (30°)**：`F_lig_eff = F_lig · 0.005 < 300` ⇒ **无骨折**（V6: 5 m/30°）。
- **低高度 + 小角度 (10°/20°)**：`F_lig_eff` 用满 `F_lig`，F_lig 大 ⇒ **骨折**（V6: 5 m/10°/20°）。
- **高高度 + 大角度**：`F_lig` 足够大，即使 30° 滑动、unload 0.005，`F_lig_eff` 仍 ≥ 300 ⇒ **骨折**（V6: 10/20 m/30°）。

**骨利用率 `ankle_bone_utilization` 仍按弯曲+剪切计算**（`σ_bend = unload·|M|·c/I + |F_lat|/A`），
作为「风险预警」读数**保留** —— 它不再直接驱动 `ankle_fracture`，但 V6 高度转变曲线的
**形式**（低高度大角度 ⇒ util < 1 ⇒ 无骨折；高高度 ⇒ util > 1 ⇒ 骨折）依然成立。
新机理走的是 `F_lig_eff` 通道，但**结构等价**（同一滑动卸载规则 + 同一相位判据）。

**韧带取「未封顶」的 M**。韧带应变用**未卸载**的力矩：
`ε = F_lig/(k·L)`、`F_lig = |M|/r`（见 §五 常量）。
⇒ 滑动**反而拉韧带**，与 [T22] 原文一致：5 m/30° 这类工况
「injuries are characterized by tension and injuries of the posterior and lateral group ligaments」
（`paper/_text/TFSR_7_1875582.txt:180-187`）。

**相对可用**（排序与机制结论，**对绝对量程不敏感**）：

  —— 该排序在本模型内平凡成立（其余部位全 0），见 §一；

**绝对不可用**：

### 根因（载荷分配系数分析，**核心新增**）

**问题陈述**：spec 期望把踝骨折从 23% 降到 ≈ 8%（[B25] 实测），
通过引入 `ankle_load_share`（载荷分配系数，0..1，无量纲）将
`f_pad` 折成踝的损伤载荷：

- **measured anchor**：`results/opensim_fe/joint_reactions_summary.csv` 的
  `ankle_r.peak_force_n / GRF_peak = 25294.9 / 53060 ≈ **0.477**`
  （OpenSim 自由体法，5 m dead-drop，详见
  `results/opensim_fe/JOINT_REACTIONS_REPORT.md` §3），
  故 MC 的 `_make_longitudinal` 设 `ankle_load_share = 0.477`。
- **Posture2D 默认 `ankle_load_share = 1.0`** ⇒ 与旧行为**逐位一致**
  （bit-identicality 锁在 `tests/test_pad2d.py::TestLoadPartition`）。

**机理修整（option (b) 撕脱而非弯曲）**：[T22] Table 4 的踝骨折临床机理是
**撕脱**（avulsion，韧带把外踝 / 内踝撕下一块），不是腓骨中段弯曲破坏。
将判据从 `bone_util ≥ 1.0`（弯曲应力）改为
`F_lig_eff ≥ ANKLE_AVULSION_LOAD_N = 300 N`
（撕脱阈值，V6 校准，modelling choice —— 非实测，
详见 `src/climbing/pad2d.py:154-201` 的常量 docstring）。
F_lig_eff 在滑动相位按 `ANKLE_SLIDE_UNLOAD = 0.005` 卸载（与 bone_util 同口径）。

**为什么 spec 期望（28%/8%）无法用单 share 解耦 —— 结构性约束**：

`peak_ligament_strain = F_lig / (k·L)` 和 `σ_bend ∝ |M|·c/I` 都是 `|M|` 的**线性**函数，
而 `|M| = f_pad · d · sinβ` 也是 `f_pad` 的线性函数。所以 `ankle_load_share`
对两者是**同比例缩放** —— 一个标量**无法**改变 fracture/sprain ratio。

为了改变 ratio 必须改**转换**机理（spec 提的 option (a)/(b)）。
本实现选 option (b)：撕脱 vs 弯曲。但即使换了机理，仍有**更深的结构约束**：

- 阈值 `ANKLE_AVULSION_LOAD_N = 300 N` 必须满足 V6 校准：
  `(5 m, 30°)` sliding 不触发（`F_lig_eff = 154 N < 300`），
  `(10 m, 30°)` 与 `(20 m, 30°)` sliding 触发
  （`F_lig_eff = 349 / 655 N > 300`）。这要求 `T ≤ 349`。
- 而 share=0.477 下 stuck 模式（`sinβ < μ_slide = 0.4` ⇒ β ≤ 23.6°）的
  F_lig 最小值 = `1892 × 0.477 ≈ 902 N ≫ T = 300` ⇒ **所有 stuck 都触发**。
- share=1.0 下 stuck F_lig 最小 1892 N 同样 ≫ 300 ⇒ **所有 stuck 都触发**。
- 故 stuck 子集**完全饱和** ⇒ fracture 率 = stuck 比例（≈ 228/345）在
  share=1.0 与 share=0.477 下几乎不变。

**实测数值（MC，N=1000，seed=20261003）**：

| share | ankle_injured | ankle_sprain | ankle_fracture | sprain/frac ratio |
|---|---|---|---|---|
| **share = 1.0（旧）** | 345/1000 = 34.5% | 345/1000 = 34.5% | 230/1000 = 23.0% | 0.667 |
| **share = 0.477（新，measured anchor）** | 345/1000 = 34.5% | 345/1000 = 34.5% | **228**/1000 = **22.8%** | 0.661 |
| **[B25] target** | 400/1000 = 40.0% | 280/1000 = 28.0% | 80/1000 = 8.0% | 0.286 |

⚠️ **诚实声明**：sprain 在 share=0.477 下**仍 100%**（`ε_min × 0.477 = 2.93 ≫ 0.14` 饱和），
fracture 从 230 → 228（**降 2 例**，即 -0.9%），**与 [B25] 8% 的 target 差 2.85x**。
单 share 解耦**结构性不可能** —— **这是有效发现**，不是拟合失败。

**包线**：结论适用于 **2–5 m** 坠落高度、`β0 ∈ {10°,20°,30°}`、
`μ_slide` 与几何常数按 `src/climbing/pad2d.py` 的模块常量取值。
**超出此包线（尤其 > 10 m 或 β0 > 30°）外推无效。**

**pending（列出，不当作已完成）**：

1. **解开 fracture/sprain 结构性耦合** —— 需要**第二个**自由度：
   (i) 改 F_lig 取样（不与 M 线性耦合，如 `F_lig_eff = F_lig^(1+α)`），或
   (ii) 改 sprain 阈值（``ε_thr`` ↑ + ``M_fail`` ↑），或
   (iii) **拆掉滑动卸载**让 avulsion 阈值可见于 share=0.477
   （但会破 V6 5/30° 单元）。**单 share 解耦已被证明不可行**
   （本节 V6 + share 数学约束证明）。
2. **`pad2d.py` 纯 LOC ≈ 510 超 250 上限**，建议拆出 `pad2d_ankle.py`。
3. **骨部位仍 0 骨折** —— 1D 轴向判据抓不到「足缘小面积接触 + 踝旋后」的**局部**机制。

## 六、P4 惯性分支（V3 / V8）与**统一根因**

### 6.1 P4 实测（`src/climbing/head_branch.py`，头颈 1-DOF 基础激励振子）

| h (m) | 峰值时刻 t−t0 (ms) | V3 ≤12.5 ms | F_neck (N) | δ_peak (mm) |
|---|---|---|---|---|
| 2 | **37.0** | ❌ | 3493 | 17.5 |
| 3 | **33.8** | ❌ | 4477 | 22.4 |
| 5 | **31.2** | ❌ | 5857 | 29.3 |
| 10 | **28.8** | ❌ | 8303 | 41.5 |
| 20 | **26.6** | ❌ | 11527 | 57.6 |

- **V8 单调性 ✅**：峰值时刻随高度**严格单调提前**（37.0 → 26.6 ms）。
- **V3 绝对值 ❌**：全部 > 12.5 ms。
- **V8 绝对值 ❌**：20 m 时 26.6 ms ≫ 5 ms。

### 6.2 刚度扫描证明 V3 **不是**颈部刚度问题

`k_neck` 从 200 → **12 000 N/mm（60×）**，2 m 峰值时刻只从 37.0 → **32.0 ms**，**饱和**。
⇒ 头峰值被**躯干减速历程**锁死，与颈部刚度无关。调 `k_neck` 救不了 V3。

### 6.3 **统一根因：工况错配（regime mismatch）**

| | [Y25] / [T22] | 本模型 |
|---|---|---|
| 落地面 | **刚性地面** | **软垫** |
| 高度 | 5–20 m | 2–5 m |
| 冲击持续 | 1–5 ms | **56–67 ms**（冲击窗实测） |
| 躯干峰值加速度时刻 | ≤12.5 ms | **23.6–32.0 ms**（冲击窗内 t−t0 实测） |

**⇒ V3/V8 的绝对时刻、以及踝骨折拆分（22.8% vs 8%）修不动，是同一个根因：**
[T22] Table 4 的「踝骨折」与 [Y25] 的 12.5 ms 都是**刚性地面**工况的量，
本模型是**软垫**工况。垫子把冲击摊到 60 ms 量级，任何峰值都不可能落在 12.5 ms 内。

载荷分配系数 `ankle_load_share` 也救不了骨折拆分 —— **stuck 子集在阈值上完全饱和**
（share=0.477 下 stuck 的最小 `F_lig` ≈ 902 N ≫ `ANKLE_AVULSION_LOAD_N` = 300 N），
fracture 率 = stuck 比例（228/345），与 share 无关。而 stuck 比例又被 **V6 锁死**：
要复现 [T22] Table 4（5m/20° 骨折、5m/30° 滑动）必须 `μ_slide ∈ [sin20°, sin30°) = [0.342, 0.5)`，
此时 {10°,20°} 卡住 / {30°} 滑动 ⇒ stuck 比例恒为 **2/3**。

**这条结论的价值**：它把两个看似独立的失败**统一**成一个可检验的物理判断，
并指出真正的出路是**补垫子物理 / 工况对齐**（= P5 抱石专用标定），
而不是继续调 P2/P4 的模型参数。
