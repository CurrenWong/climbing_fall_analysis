## 二、三旋钮不敏感证据（决定"结构性"判定）

| 旋钮 | 扫描范围 | 骨折率 / 骨折计数 | 相对变化 |
|---|---|---|---|
| **撕脱阈值 `T`** | 154 → 349 N（**≈2.3×**） | 229 / 229 / 228 / 228 / 228 | **仅 1 例差**（例外 = trial 611，sliding eff=166.5，仅 T ≤ 165 越阈） |
| **垫刚度 `α_pad`** | 1 / 10 / 30（**30×**） | 22.8 / 23.0 / 23.2 % | **+0.4 pp**（踝损伤恒 34.5 %） |
| **载荷分享 `share`** | 1.0 / 0.477（**≈2×**） | 230 / 228 | **−2 例（−0.9 %）** |

> **合计**：三旋钮调节范围跨 **≈10³**，骨折率总变动 **≤ 1 pp**（22.8–23.2 %）。
> ⇒ 并非"旋钮没调对"，而是**输出对旋钮不响应**。出处：`PAPER_CRED_TODO.md`（阈值）、`最终结论` §三（垫刚度）、`P2_踝结论` §四（share）。

## 三、根因（为何是结构性，改不动）

1. **判据结构：骨折 ≡ 卡住（stuck）**。撕脱判据为 `F_lig_eff ≥ T`；而 stuck 子集**完全饱和**
   —— `share=0.477` 下 stuck 的最小 `F_lig ≈ 902 N ≫ T = 215 N` ⇒ **所有 stuck 都触发**。
   ⇒ `fracture 率 = stuck 比例 = 228/345 ≈ 2/3`。
2. **stuck 比例被 V6 锁死**。复现 [T22] Table 4（5 m/20° 骨折、5 m/30° 滑动）要求
   `μ_slide ∈ [sin20°, sin30°) = [0.342, 0.5)` ⇒ {10°,20°} 卡住 / {30°} 滑动 ⇒ **stuck 恒为 2/3**。
3. **单 share 解耦数学上不可能**。`peak_ligament_strain = F_lig/(k·L)` 与 `σ_bend ∝ |M|·c/I` 都是
   `|M| = f_pad·d·sinβ` 的**线性**函数 ⇒ `ankle_load_share` 对其**同比例缩放**，一个标量**无法**改变
   fracture/sprain ratio（`P2_踝结论` §四 已证明）。
4. **工况错配**。[T22] 的"踝骨折"是**刚性地面**工况量；本模型是**软垫**工况（冲击摊到 ~60 ms）。
   ⇒ 与 P-5（头颈峰时）共享同一根因（`目标重构` §二 / `P2_踝结论` §6.3）。

⇒ **2.85× 来自上述结构 + 工况的叠加，任一参数标定都消不掉**；故输出 = **上界**，偏差因子**入账**。
